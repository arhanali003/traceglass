# 0.2.0b1 — draft beta release notes

Not published. This proposed beta includes the previously unreleased bundle
verifier and the early-adoption reliability improvements.

- Recovery rejects special-file roots, checks file identity/change during reads,
  and explicitly skips Windows reparse entries.
- Collection retains a manifest after per-directory creation errors, continues
  unrelated entries and records cleanup failures.
- Recovery now returns exit 2 when skips are recorded. This is an intentional
  automation behavior change; review the manifest instead of assuming exit 0.
- Verifier rejects Windows-ambiguous trailing dots/spaces and device names on all
  platforms, including POSIX bundles containing those unusual filenames.
- All original helper entry points expose `--version`.
- A deterministic ZIP build preserves the skill layout with a SHA-256 inventory;
  a clean unpack/install smoke scenario verifies the packaged tools.
- Add beta test scenarios, contributor/security guidance and development checks.

No runtime dependency, new analysis engine, model service or automatic behavior
comparison was added. Existing command names and manifest keys are preserved.

Known limits: live client compatibility is unverified; outputs are not authenticated;
filesystem operations are not safe against every concurrent attacker; total disk
usage is not bounded. Windows junction integration must run on Windows. See
`QA_REPORT.md` in the repository for actual local verification results.
