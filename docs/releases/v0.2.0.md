# v0.2.0 — Bundle evidence verification (draft)

Status: historical draft, not tagged or published. Superseded by
[0.2.0b1 beta notes](v0.2.0b1.md). Test counts below describe the earlier verifier
change, not the current beta suite.

AI coding agents can now recheck a saved bundle before resuming an investigation.
Run `verify_bundle.py --bundle <collector-output>` to obtain JSON results and a
process exit code. Modified or missing files and recorded collection failures
prevent a successful result.

Install Source Recovery using `scripts/install.py --skill source-recovery` with
`--client` and `--project`, or run the verifier directly from this checkout.
Existing installations must be backed up/moved before reinstalling. Python 3.9+
is required; no additional packages are needed.

See the [usage contract](../bundle-verification.md) and
[example](../../examples/verify-bundle.md).

## Validation

The local suite contains 38 passing tests, including 16 new verifier tests.
GitHub Actions is configured for Python 3.9/3.13 on Linux, macOS and Windows.
Actual remote run status must be checked on the PR; configuration alone is not
proof of a successful run. Some platform-specific tests can skip.

## Limits and compatibility

No installer or collector interface changes. The verifier accepts collector
manifests only and rejects non-portable paths. It checks listed file bytes, not
extra files, original source completeness, licensing, authenticity or application
behavior. Use a stable local bundle: concurrent hostile filesystem mutation is
outside its guarantees. No new live AI-client compatibility is claimed.

The existing MIT license and upstream attribution are unchanged. No proprietary
application files or third-party dependencies were added.
