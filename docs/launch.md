# Publishing checklist

Suggested repository name: `traceglass`.

Suggested About text: “Evidence-first reverse-engineering skills for Codex, Claude Code, and Antigravity. Trace features, compare releases, explain what the evidence supports.”

Suggested topics: `reverse-engineering`, `agent-skills`, `codex`, `claude-code`, `antigravity`, `binary-analysis`, `electron`, `developer-tools`.

Before publishing, review the license and name, run the checks, and verify skill discovery in each available client. Keep unverified clients explicitly marked. Set the repository description and topics. Use the editable hero artwork as the basis of a social preview.

For a credible launch, record a short real investigation against a redistributable artifact: prompt, evidence, result. Link the walkthrough prominently. Share what it answers and its limits. Invite users to contribute small fixtures and client compatibility reports. Avoid fabricated usage numbers, performance claims, testimonials, or star targets presented as guarantees.

Draft announcement:

> I built Traceglass, a portable reverse-engineering skill for Codex, Claude Code, and Antigravity. It helps agents trace a feature and separate what the evidence shows from what remains unknown. It includes a tiny local example and an optional REA integration. I’d love feedback on the reports and setup experience.
